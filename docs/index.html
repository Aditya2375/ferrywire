This browser lab simulates virtual packets. It does not send UDP, open sockets or contact another device. The Python CLI does use real 127.0.0.1 UDP. Both implement the same frame format and bounded state machines.

03 / Packet-by-packet evidence

0 EVENTS

Read top to bottom. A duplicate ACK never triggers a new DATA send. Retransmissions happen only when the sender's timer expires. Old or out-of-order data cannot append bytes twice.

ON THE WIRE

Thirty-one bytes
around a chunk.

27 bytes of header. Up to 512 bytes of payload. 4 bytes of CRC-32. The START frame announces total size and a SHA-256 digest; a fresh 16-byte session ID separates transfers.

FRY1magic + version / 4 BKIND1 BSESSION16 BSEQ2 BTOTAL2 BLEN2 BPAYLOAD0-512 B, by frame typeCRC-324 B

Big-endian integers, strict lengths, counters and frame shapes. CRC-32 and an announced SHA-256 digest detect accidental corruption. Neither provides authentication or encryption; another local process can interfere or forge packets.

SMALL ON PURPOSE

Real, local endpoints

The Python standard-library CLI binds and sends only to IPv4 127.0.0.1. One transfer, at most 16 KiB. No DNS, remote host option, network filenames or filesystem writes.

Bounded failure

One outstanding frame. Six attempts per frame, a 30 s sender deadline and at most 4,096 incoming datagrams per endpoint. No promise that arbitrary loss eventually recovers.

Know the edges

No encryption, authentication, restart recovery, multiplexing, sliding window, RTT estimator or Internet congestion control. Use a standard transport for real networks. This is a trusted-local-machine protocol lab.

OUTSIDE THE SIMULATION

Run the real crossing.

Python 3.10+ on Linux. Start the receiver, use its reported port, then send bytes from another terminal. The receiver prints ready JSON first, then verified payload as base64 JSON. No files are created.
